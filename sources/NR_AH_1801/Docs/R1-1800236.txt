Introduction

In this contribution, we discuss some remaining issues and possible approaches to complete the related parts in specifications regarding layer-to-antenna port mapping.

In TS 38.212[2], DMRS port allocation information fields for different configurations of DL-DMRS-config-type and DL-DMRS-max-len parameters are interpreted in Table 7.3.1.2.2-1, Table 7.3.1.2.2-2, Table 7.3.1.2.2-3 and Table 7.3.1.2.2-4 respectively. Wherein the DMRS port(s) being scheduled are indicated by the antenna port allocation index in the DMRS table for each case. However, it doesn’t imply a reasonable order of DMRS ports for data transmission. Also, in TS 38.214[3], corresponding description on the above-mentioned procedure for determining the set of antenna ports [FIG:5c267d7d875c5a7a2f69] is not included yet. Actually, as shown below, the ordering of DMRS ports in vector [FIG:44c54776a200b3a0bef3] has potential impact on performance and implementation especially for 2-codeword transmission with multi-TRPs/panels.

Unfortunately, it seems that we still have no discussion on it. In addition, similar situation applies to UL as well.

Observation 1: Ordering of DMRS port in is still an open issue.

With the scheduled DMRS port(s) indicated via DCI, we need to consider the potential impact of port ordering on multi-TRP/panel transmission. For example, for non-coherent transmission of 2 codewords, it would be desirable to constrain each codeword in one TRP/panel, especially considering the potential difference in channel qualities of different TRPs/ panels. In such case, if one codeword is mapped into more than one TRPs/panels, the link adaptation performances would be affected by more unbalanced qualities between two parts of layers from two TRPs/panels and inherent mismatch of MCS for the codeword.

Based on the codeword-to-layer mapping procedure in [1], for transmission with odd number of layers, codeword 0 always has fewer layers. Therefore, keep the above consideration in mind, it’s reasonable to keep the DMRS ports within the QCL group with fewer number of ports in the front of the ordered DMRS port vector [FIG:5b4d68a4578cf7565f71] . Even though the configuration of QCL group is still open, as stated in [1], at least the UE can assume that DMRS ports within one CDM group are QCL-ed. Therefore, for the cases where two CDM groups are allocated to the UE, we can order the allocated DMRS ports in the way that DMRS ports within the CDM group with fewer DMRS ports always located in the front of DMRS port vector for multi-TRP/panel transmission.

For single-TRP/panel or single-QCL group based transmission, on the other hand, no additional complexity or performance loss are induced with such ordering principle. Therefore, we can apply the same rule for both cases in 2-codeword transmission.

Observation 2: For single-TRP/panel or single-QCL group based transmission, no additional complexity or performance loss are induced with specific ordering principle.

If DMRS configuration type2 is used, things are getting a little bit complicated for 2-codeword transmission with scheduled DMRS located in all the three CDM groups. Fortunately, based on Table 7.3.1.2.2-3 and Table 7.3.1.2.2-4 in [2], only two cases fall into such situation, namely rank-5 and rank-6 transmissions with indices 0 and 1 respectively.

In Table 7.3.1.2.2-3 and Table 7.3.1.2.2-4 of [2], for DL-DMRS-config-type=2, value=0 corresponds to the case where DMRS ports 0-4 are being scheduled. To ensure that each codeword is mapped to only one QCL group, we can order the available ports as: 1000, 1001, 1002, 1003, 1004. Wherein ports {1000, 1001}, {1002, 1003} and {1004} are with CDM group 0,1 and 2 respectively, and the two DMRS groups are {1000, 1001} and {1002, 1003, 1004}

In Table 7.3.1.2.2-3 and Table 7.3.1.2.2-4 of [2], for DL-DMRS-config-type=2, value=1 corresponds to the case where DMRS ports 1000, 1001, 1002, 1003, 1004, 1005 are being scheduled. In such case, if two QCL groups are configured, it’s impossible to divide the 6 ports evenly among both QCL groups. That is, one of the codewords have to be mapped to more than one QCL groups. Each of the DMRS groups could have 2 or 4 DMRS ports then.

Except for the above case, there is still one more issue needs to be mentioned for rank adaptation operation in multi-TRP/panel transmission. Take rank-5 transmission with 2 CDM groups being scheduled to one UE and higher-layer parameters DL-DMRS-config-type=2 and DL-DMRS-max-len=2 as an example, we can order the 5 port available as 1002, 1003, 1000, 1001, 1006 to make sure that each codeword is mapped to a group of QCL-ed ports within one CDM group. In such case, ports {1002, 1003} and {1000, 1001, 1006} are with CDM group 0 and 1 respectively.

With rank adaptation, the UE might be allocated with DMRS ports 0,1,2,3,6,8 in the next scheduling occasion dynamically. According to the physical resources mapping of DMRS in [1], DMRS ports{1000, 1001, 1006} and {1002, 1003, 1008} belong to CDM group 0 and 1 respectively. Without any restriction, we can use the orders like 1000, 1001, 1002, 1003, 1006, 1008 or 1002, 1003, 1008, 1000, 1001, 1006 for DMRS port vector [FIG:723fb334b0397eb3bf94] . However, choice among alternative orders may have impact on backhaul requirement. For instance, if codeword 0 and 1 were mapped to DMRS ports {1002, 1003} and {1000, 1001, 1006} in previous scheduling with 5 layers, and the transmission rank is adapted to 6 in current scheduling, using the order 0,1,6,2,3 may result in a mapping switching between each of the transport blocks and its corresponding TRP. This may lead to additional load to exchange transport blocks on backhaul. To avoid that issue, we may choose to order the DMRS ports like 1002, 1003, 1008, 1000, 1001, 1006.

Observation 3: The ordering of DMRS ports in vector [yP(0)(i)…y(Pv-1)(i)]T has potential impact on performance and implementation for 2-codeword transmission with multi-TRPs/panels.

Proposal 1: DMRS ports should be ordered so that a codeword uses port(s) that are CDM-ed or QCL-ed (as much as possible).

Proposal 2: Impact on practical implementation, e.g. extra load on backhaul, needs to be considered in ordering the DMRS ports.

As we already have a set of concrete tables for DMRS ports allocation, where DMRS port(s) being scheduled are given by antenna port allocation indices for each configuration of higher-layer parameters DL-DMRS-config-type and DL-DMRS-max-len, to minimize the specification impact and also the corresponding work load to the editors, instead of duplicating the descriptions and tables in TS 38.214 redundantly, we propose to indicate the set of antenna ports [FIG:5fddf54442b0c5941c93] for each case in Table 7.3.1.2.2-1, Table 7.3.1.2.2-2, Table 7.3.1.2.2-3 and Table 7.3.1.2.2-4 in TS 28.212[2]. Furthermore, we can replace the fields of “DMRS port(s)” directly with the “set of antenna ports [FIG:62f6155bf164e76e8d6d] ”.

Proposal 3: Indicate the set of antenna ports [FIG:4344613f993ddf227223] for each case in Table 7.3.1.2.2-1, Table 7.3.1.2.2-2, Table 7.3.1.2.2-3 and Table 7.3.1.2.2-4 in TS 28.212[2].

Proposal 4: Replace the fields of “DMRS port(s)” directly with the “set of antenna ports [FIG:1b8a5b0ee19815677eeb] ” in Table 7.3.1.2.2-1, Table 7.3.1.2.2-2, Table 7.3.1.2.2-3 and Table 7.3.1.2.2-4 in TS 28.212[2].

Conclusions

In this contribution, we discuss the remaining details regarding layer-to-DMRS port mapping. In addition, exemplary DMRS tables (Table 1-4) are presented. Based on the discussion above, we have the following observations and proposals.

Observation 1: Ordering of DMRS port in is still an open issue.

Observation 2: For single-TRP/panel or single-QCL group based transmission, no additional complexity or performance loss are induced with specific ordering principle.

Observation 3: The ordering of DMRS ports in vector [yP(0)(i)…y(Pv-1)(i)]T has potential impact on performance and implementation for 2-codeword transmission with multi-TRPs/panels.

Proposal 1: DMRS ports should be ordered so that a codeword uses port(s) that are CDM-ed or QCL-ed (as much as possible).

Proposal 2: Impact on practical implementation, e.g. extra load on backhaul, needs to be considered in ordering the DMRS ports.

Proposal 3: Indicate the set of antenna ports [FIG:28291818b3cceeb23205] for each case in Table 7.3.1.2.2-1, Table 7.3.1.2.2-2, Table 7.3.1.2.2-3 and Table 7.3.1.2.2-4 in TS 28.212[2].

Proposal 4: Replace the fields of “DMRS port(s)” directly with the “set of antenna ports [FIG:16d9b5dbabf4ddf661bc] ” in Table 7.3.1.2.2-1, Table 7.3.1.2.2-2, Table 7.3.1.2.2-3 and Table 7.3.1.2.2-4 in TS 28.212[2].

Observation 4: Compared with the originl Table 7.3.1.2.2-1, Table 7.3.1.2.2-2, Table 7.3.1.2.2-3 and Table 7.3.1.2.2-4 in TS 28.212[2], all the ordering changes could be related to 2-codeword transmission only.
